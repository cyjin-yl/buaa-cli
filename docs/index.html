buaa-cli

A Rust command line for BUAA workflows, with structured output and conservative request control.

Know the boundary. Timed-input replay, archive lookup/capture, marks/GPA offline engine, pinned Fengrubei template retrieval, authorized local recording-catalog search and the authoritative teaching/research organization directory are implemented and offline-tested. Gateway usage/login/logout code is offline-loopback-tested but live-unverified; campus authentication has not been attempted. Governed CDX pagination/date search has been observed. One exact 1997 homepage Memento replay has matching attribution, independently verified resource bytes and offline reuse. Complete history, archived announcement coverage and current competition-format compliance remain unverified.

Build and discover

Use Rust 1.89 or newer on Linux, or the public devcontainer definition. Dependency downloads are public and require no campus credentials.

cargo fetch --locked
cargo build --locked --offline
./target/debug/buaa help
./target/debug/buaa capabilities
./target/debug/buaa schema

Normal commands do not require an interactive prompt. Data goes to JSON/NDJSON stdout; sanitized typed errors go to stderr.

Command examples

Replay local input

printf '[0]first\n[0.25]second\n' | ./target/debug/buaa timed-input

Add --raw for newline-delimited text, or --dry-run to validate and emit the schedule without waiting. The complete input is validated before any event is emitted.

{"type":"timed_input","sequence":1,"at_ns":0,"text":"first"}

Look up an archived page

This is a synthetic URL and a cache-only example; an uncached query returns unavailable rather than inventing history.

printf '%s\n' '{"url":"https://college.example/notice/42.html"}' \
  | ./target/debug/buaa archive lookup

--online explicitly permits authorized archive reads on a cache miss; --refresh conditionally revalidates. Only approved Internet Archive HTTPS routes are allowed. No original campus host is contacted.

Inspect or fetch the pinned Fengrubei release

./target/debug/buaa fengrubei info
printf '%s\n' '{"output":"/home/operator/private/template-v1.0.3.zip"}' \
  | ./target/debug/buaa fengrubei fetch

Fetching is cache-only unless --online is explicit. The output must be new inside an existing owner-controlled, non-writable-by-others, symlink-free parent. BUAA CLI verifies the original ZIP but never unpacks, executes or compiles it.

Inspect cached gateway usage

./target/debug/buaa gateway usage

Login is never automatic: a typed gateway resume-auth arms one final credential submission, and credentials are bounded JSON on stdin. Logout commits require explicit --online; unknown outcomes can only be reviewed through a local-only flow that keeps remote state unknown. No real account operation was performed for this iteration.

Search an authorized local recording catalog

printf '%s\n' '{"catalog":"/private/catalog.sqlite","query":"linear algebra","authorized":true}' \
  | ./target/debug/buaa recordings search

Supply an existing local catalog you may read. Authorization is an operator attestation, not proof of media rights. Hashes and object locators remain catalog declarations; no media object is fetched.

Account safety

  • One in-flight request; at least five seconds after completion. Background observations are at least fifteen minutes apart.
  • Cache first. Honor Retry-After; a 429 without a valid explicit delay imposes at least thirty minutes.
  • Authentication rejection and challenge signals latch. No automatic login refresh, challenge bypass or fabricated attendance or course completion.
  • Every process using an account must share one governed identity and state domain. Worktrees must not create independent limiters.
  • Unknown outcomes, reboot identity mismatch and corrupt history fail closed. Known old-boot history has an explicit offline typed plan/commit that preserves original bytes and full waits; it cannot clear unknown/corrupt history. Do not delete state to regain throughput.
  • Legitimate campus write capabilities remain in scope, but none is requested or needed for this source iteration; assignment submission stays with the owner. Future enrolment, evaluation, submission, ticket and destructive-drive operations need preview, typed intent, plan/commit separation and idempotency.

Credentials and private media stay outside public source. The devcontainer build does not copy private HOME, model, GitHub, SSH or Life configuration.
